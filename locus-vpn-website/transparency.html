Why no traffic data appears above

There is no row for "destinations visited" or "IP addresses", because those records do not exist. Servers hold session state in memory only and write nothing to disk, so there is no archive to search and no backup to hand over. A request that asks for browsing history or a connection log receives a statement that the data does not exist.

How we handle a request

  1. We check the order is valid in the jurisdiction that issued it, and that it names an account rather than asking for bulk data.
  2. Where the order is invalid or overly broad, we push back and ask for it to be narrowed.
  3. If it is valid, we provide what the account system holds and nothing further.
  4. We notify the account holder before disclosure, unless we are legally barred from doing so.
  5. Every request is logged internally and counted in the next report.

Warrant canary

We publish this report on a fixed schedule rather than to signal a specific event, and we do not operate a canary statement. A scheduled report cannot be silently suspended without the gap becoming visible, which is the property a canary is usually meant to provide.

Audits supporting this report

  • Annual independent security audit of the client and infrastructure, published in full with our response to each finding.
  • Reproducible builds, so the running binary can be checked against published source.
  • Public bug bounty, with payout amounts listed on the report page.
